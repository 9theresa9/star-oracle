# SSH-only Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Follow test-first implementation and independent review.

**Goal:** Add the owner-approved persistent SSH-only deployment without weakening public HTTPS.

**Architecture:** A strict API mode and cookie policy, isolated deployment launcher and ingress, offline transport-cutover revocation, and runtime UI notice. CI verifies each layer and exports tested runtime images.

**Tech Stack:** Existing React 19/Vite, NestJS 11, Better Auth 1.7.7, Prisma/MySQL 8.4, Redis 7.4, Docker/Nginx.

**Spec:** ../specs/2026-10-09-ssh-only-design.md

## Global Constraints

- Only `http://localhost:17777` is accepted in SSH mode; default mode remains `https`.
- Keep administrator 2FA, passwords, CSRF, rate limits, private actor/session checks and closed registration.
- No real account/secret/server changes, merging or deployment in this task.
- A separate Compose file and actual network inspection must establish isolation; a hostname alone never does.

## Review Focus

- Docker direct-routing and extra network attachments: ingress peer filtering plus real network tests.
- Normalized host aliases, duplicate Host and empty forwarding headers: literal/raw-header tests.
- Existing cookies renamed into the new family: offline revocation and fresh TOTP tests.
- Interrupted revocation and partial Redis failure: preserve retry discovery and keep APIs stopped.
- Public HTTPS regression and cached localhost HSTS: unchanged default policy, explicit upgrade guidance.
