# 性能与代码整理

本轮在原有前后端分离架构上整理加载、查询和公共计算。全部功能继续位于 `feat/comprehensive-oracle`，统一通过 PR #4 review。

## 优化范围

- 前端非首页路由和登录 SDK 按需加载，安装提示样式与运营后台样式分离；入场动画交给 CSS，复制提示计时器与 PWA 注册避免重复工作。页面模块下载失败时保留导航，并提供中文刷新提示。
- 私人记录在服务器确认后局部更新已载入缓存，保留分页游标和账号隔离；改变筛选成员的操作仍从服务器刷新。
- GET 查询接入取消信号，页面切换或筛选变更时停止过时请求。
- 统计复用分组结果，列表按所需字段投影；稀疏搜索先筛选，再读取匹配记录的完整内容。
- 元数据更新减少重复读取，AI 租约续期合并 Redis 往返，事务/额度/幂等规则保持原语义。
- 易经派生分析复用已验证结果，格式器复用仅缓存公开时区配置，不缓存私人正文。
- 为实际查询补充索引，并保留独立迁移。

## 可复现验证

固定基线提交为 `a639057e9884efb53fb712d7a41b0d16e8cbf0c3`。CI 以相同 Node 24、锁文件与 `NODE_ENV=production` 构建前后两版。

`scripts/measure-web-bundle.mjs` 计算首页入口及其静态 import 闭包的 JS/CSS 原始和 gzip 字节，同时列全部动态块。首页变小不能通过遗漏静态预加载依赖来计算。

`scripts/compare-api-performance.mjs` 使用独立临时源码副本和隔离 MySQL/Redis。它只在 CI 测试环境、loopback 的 `star_oracle` 数据库执行，创建专用账户与 651 条记录；测量真实 SQL 次数、解密次数及大字段读取，逐项核对两版返回结果摘要一致，最后清理自己的数据。

`scripts/compare-domain-performance.mjs` 对全部 64 卦的三种动爻模式逐项比较基础解读摘要，并比较不同时间及时区的起卦输出，记录分析次数和格式器构造次数。

日志计数只在临时源码副本启用，生产 Prisma 客户端继续关闭查询日志；报告不记录 SQL 参数或私人正文。两版服务使用相同的新数据库 schema，查询次数对比不冒充索引的独立加速幅度。局部 CI 延迟仅供定位，不承诺公网响应时间。

性能 JSON、迁移和端到端报告位于 CI 的 `production-review` artifact，保留 14 天；最终 PR 说明记录实测结果及对应代码 SHA。

## 维护边界

私人内容仍加密保存；管理员权限、跨账号隔离、来源删除、AI 幂等与每日额度保持回归覆盖。AI 模型推理速度还取决于实际渠道、模型和网络，正式运行需配置服务器和凭据。
