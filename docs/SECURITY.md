# 安全实现与验证范围

本文件记录当前代码的控制与证据，不承诺“无漏洞”。最终 CI 通过及真实部署验收应同时满足，之后持续更新依赖与平台。

| 风险 | 实现 |
|---|---|
| 伪造用户、角色或读取他人记录 | Better Auth 会话；每次 API 从 MySQL 核验当前用户、disabled、真实 session；每条记录查询含 userId；公开注册和在线身份字段修改关闭 |
| 停用/降权后旧会话继续生效 | 停用事务删除 session；角色每次从 DB 读取；不使用 15 分钟仍可用的静态角色 JWT |
| 浏览器令牌泄漏 / CSRF | HttpOnly + Secure(生产) + SameSite=Lax；禁用 cookie 会话缓存；固定可信来源；业务写请求要求准确 Origin 和 JSON；不会把 bearer 写到 localStorage |
| 管理员账户被盗 | 生产必须启用已确认的 TOTP；一次性恢复码；服务器离线提权并撤销旧会话；普通管理员账户不能由前台停用或删除 |
| 注入与非法输入 | Zod 严格字段、UUID、长度与页大小；Prisma 参数化查询；React 默认转义；不渲染模型 HTML；公开前端 CSP / frame 限制 |
| 私密正文泄漏 | 问题、日记、解读、备注/标签、追问、行动、反馈/回复、回顾输入/输出及内部AI结果使用AES-256-GCM + 所属用户/记录/字段AAD；管理员只读主动共享内容及主动提交的反馈；技术日志与审计不保存正文 |
| 重复抽取、并发覆盖 | DB唯一用户日期与幂等请求约束；32牌阵由服务端生成，数字/时间起卦严格复算；日记/元数据/行动/反馈/内容乐观版本更新；AI请求绑定来源与内容指纹，完成复用、生成中409，失败新尝试需新ID |
| 暴力尝试 / 多实例限流 | Redis 原子限流；用户名登录与两步验证端点更严格；注册/邮件重设端点关闭；IP 从可信网关链取值并覆盖客户端同名头；限制短期窗口 |
| AI账单与响应攻击 | 本人归属、明确同意、固定证据；30秒超时、100KB响应体、严格JSON/完整唯一引用；最多4个TTL租约；全站日预算与free/plus/credits消费同一Serializable事务、同一captured上海账期；失败也占尝试额度，避免隐形重试消费 |
| 隐私记录导出/删除 | 本人全关联导出，含全部日记与兑换历史；过量明确拒绝413、不静默截断；删账户级联业务数据；删探索/回顾级联相应AIRequest；清空日记保留每日牌面，既有独立回顾需单独删除；恢复后撤销全部会话 |
| 公网数据库 / 容器横向访问 | 仅网关公布端口；MySQL/Redis密码；应用/迁移DB账号分离；网关/静态前端无法直接连接数据库网络；API不接收数据库root/迁移密码；API/Web非root、只读文件系统、禁提权、去多余capability |
| 依赖与供应链 | 版本及锁文件、CI audit；GitHub Actions只读仓库权限、官方Action固定完整提交SHA；框架和认证依赖单独锁定；容器基镜像仍需持续扫描与按digest记录发布 |
| 兑换超发/额度并发 | 安全随机兑换码，仅存SHA-256与提示尾段；用户码唯一、usedCount条件递增、余额/期限/账本/审计Serializable事务与有限重试；停用/过期拒绝，普通用户没有发码或调额接口 |
| PWA缓存泄漏 | Service Worker只缓存公开index外壳与白名单静态资源；API/auth、带查询串与token路径不缓存；私有路径离线不返回缓存页面；外部源不缓存，资产获取不带Cookie |
| 运维失误 | 启动拒绝不安全生产配置；持久卷、加密备份、密钥单独保管、恢复/回退说明；不用数据库管理工具暴露公网 |

## 私密数据与回顾快照生命周期

私密正文以应用层AES-256-GCM保存，包括Reading问题/初次解读/备注/标签、DailyEntry日记、ReadingConversation问题/回答、ActionPlan标题/详情、Feedback正文/管理员回复、ReviewReport输入快照/结果、AIRequest内部结果。AAD绑定用户、记录和字段，不能把甲用户密文移到乙用户记录使用。用户名、昵称、旧账户邮箱/新账户内部非投递标识、心情类别、日期、类型、期限、共享标记和统计字段并非全部密文；管理端仅使用其授权需要的基本信息或聚合统计。这不是端到端加密。

AI初次解读与追问的AIRequest绑定Reading外键；周/月回顾绑定ReviewReport外键，均onDelete:Cascade。本人删除探索时会清除其追问和内部AI结果；本人删除回顾时会清除该回顾输入快照、输出及内部AI结果。已有独立行动保留，但readingId置空。账户删除级联业务数据，备份中的历史副本则按运维留存策略到期清除。

回顾的inputCipher保存首次同意范围内的加密输入快照，包括选定统计、有限探索证据与上下文。默认不纳入日记正文；includeJournal=true才纳入最多最近10天、每条500字，界面需额外勾选。快照用于请求幂等与中断恢复，后续新增记录或修改原日记不改变已生成的历史回顾。要清除旧快照与其解读，本人须删除对应回顾；只清空原日记或删除原探索不会同步改写这些独立历史回顾。

管理员没有日记、私人标签/备注、追问、行动、回顾或inputCipher读取接口。本人导出包含可见回顾结果，不重复导出内部inputCipher或AIRequest缓存；不导出密码、TOTP秘密、会话令牌、完整兑换码或codeHash。导出完整关联数据（占卜、日记、追问、回顾、行动、反馈、会员、账本、兑换历史），总行数>20000、预估私文>12MB或实际JSON>20MB明确拒绝413，不用静默截断制造“完整”结果；大型账户需安排适合的分批导出流程。

## AI额度、幂等与兑换

模型请求在获取租约后捕获一次上海账期，并将同一日期传给全站AIUsage与用户UserAIUsage消费；等锁跨午夜不会拆成两天记账。每日free 5次、有效plus 20次，用完后才扣credits；全站预算仍独立限制总请求数。认领AIRequest、全站预算、本人额度与账本在同一Serializable事务内完成。调用失败也消耗已认领的尝试额度；删除内容不退额度、不删除财务流水或无正文审计。来源删除后AIAllowance仍保留已消费requestId，旧标识不能用于新请求，返回409，不再扣费或调用模型提供商。

requestId作用域是本人；来源Reading/ReviewReport与问题、证据、上下文纳入内容指纹。相同完成请求直接复用，内容或来源不符409，pending不重复调用模型。中断超过120秒的普通AI尝试转失败，明确新尝试使用新requestId；回顾使用固定inputCipher恢复，避免重读变动资料导致恢复错配。持续失败或超时不能靠同ID隐形重复请求外部模型。

兑换码使用144位随机熵，明文只在创建响应显示，数据库保留SHA-256与尾段提示。同用户同码唯一，最大使用数/停用/过期条件与增加余额/期限、兑换记录、账本、审计在事务中原子处理；余额有上限，管理员调整记录差额。本人兑换与流水游标核验归属。当前支付接口只报告未开放，不生成订单或付款成功记录。

## PWA与浏览器持久缓存

Service Worker仅为公开静态外壳提供离线回退；缓存版本升级会清除旧public缓存。/api/、/auth/、带查询串或token路径、外部来源、非GET不进入持久缓存。静态资产只允许白名单与带内容哈希的文件，获取时credentials:omit；私人导航离线返回不缓存的503提示，不回退为私人页面。安装需要HTTPS，iPhone通过Safari添加到主屏幕；私人记录与AI服务需要联网。此控制描述的是Service Worker CacheStorage，不能代替会话隔离或服务器权限。

## 测试应包含的证据

- 78牌/64卦、32牌阵完整位置与引用、4096组六爻、硬币分布、随机拒绝采样、384种数字上下卦/动爻组合、时间时区/无效日期、互错综推导。
- 真实 MySQL / Redis：跨用户读/改/删/AI都失败，注入角色不生效，重复请求只建一条记录，每日并发领取同一条，过期日记版本返回409。
- 管理员只能读主动共享内容，停止共享后不可列出；管理员没有日记写接口；停用即失效、降权即禁止。
- AES 篡改认证、上海午夜边界、共享限流计数。
- 受控HTTPS模型：引用不符/遗漏/重复拒绝、32牌阵与追问固定证据、完成不再调用、预算耗尽不调用、并发状态、跨午夜统一账期、回顾快照中断恢复、删除探索/回顾清除关联AI结果。
- 真实MySQL/Redis：额度/会员到期、并发扣减与最大次数兑换、不重复发放、额度账本、完整导出含兑换历史、私文加密、公开内容草稿不可读、反馈与管理员权限、PWA不缓存私有请求。
- TOTP enroll / 登录前置挑战 / 恢复码一次性使用。
- Chromium 桌面、iPhone WebKit、320px窄屏：主页、抽牌、六次起爻、账户/云端日记流程与无横向溢出。
- Docker 构建、正式配置校验、网关配置及带数据库的镜像运行验收。

## 仍需要真实环境验证

受控账户初始化、模型账号策略/计费、TLS与域名、国内网络可达性、服务器防火墙、日志/备份策略、容量与压力、外部渗透测试。源码测试不能代替这些条件。

应用层加密不阻止持有服务器密钥的运维人员解密，也不替代磁盘/备份加密。AUTH_SECRET / DATA_ENCRYPTION_KEY 必须分开保管；直接更换数据密钥会使旧记录无法解密。

密钥轮换需要先备份与验证恢复，再安排受控维护：使用旧数据密钥解密上述全部私文列，按原字段AAD用新密钥重加密，核对数量/样本后切换配置。DATA_ENCRYPTION_KEY同时派生AI幂等HMAC指纹；轮换还须迁移或兼容旧指纹校验，不能只重加密正文。AUTH_SECRET轮换会影响Better Auth认证及其加密数据（例如TOTP），应按锁定库版本支持的方案处理并撤销旧会话/短期认证缓存。当前没有一键密钥轮换工具，未经演练不能直接替换.env中的两个值。自托管服务器管理员权限需限制到实际需要的人员。

当前每 IP 的固定窗口限流配合客户端 IP 会在大型 NAT 网络下影响合法用户，应根据真实流量调整，并增加网关/WAF防刷；不宣称单独限流等于全网DDoS防御。应用有100KB模型响应上限和32KB请求上限，但仍需要网关连接与资源限制。

扫描失败应修复后才发布，禁止为了显示通过而关闭安全检查或忽略高危公告。CLI 使用的 deepmerge-ts/effect 安全 override 需要随 Prisma 更新重新确认兼容性；目前以真实迁移验证，未把高危旧版本保留下来。
