# 安全实现与验证范围

本文件记录当前代码的控制与证据，不承诺“无漏洞”。最终 CI 通过及真实部署验收应同时满足，之后持续更新依赖与平台。

| 风险 | 实现 |
|---|---|
| 伪造用户、角色或读取他人记录 | Better Auth 会话；每次 API 从 MySQL 核验当前用户、disabled、真实 session；每条记录查询含 userId；角色字段不可通过注册输入 |
| 停用/降权后旧会话继续生效 | 停用事务删除 session；角色每次从 DB 读取；不使用 15 分钟仍可用的静态角色 JWT |
| 浏览器令牌泄漏 / CSRF | HttpOnly + Secure(生产) + SameSite=Lax；禁用 cookie 会话缓存；固定可信来源；业务写请求要求准确 Origin 和 JSON；不会把 bearer 写到 localStorage |
| 管理员账户被盗 | 生产必须启用已确认的 TOTP；一次性恢复码；服务器离线提权并撤销旧会话；普通管理员账户不能由前台停用或删除 |
| 注入与非法输入 | Zod 严格字段、UUID、长度与页大小；Prisma 参数化查询；React 默认转义；不渲染模型 HTML；公开前端 CSP / frame 限制 |
| 日记/问题泄漏 | AES-256-GCM 应用层加密 + 所属用户/记录/字段 AAD；管理接口不提供私人日记或未共享内容；技术日志与审计不保存正文 |
| 重复抽取、并发覆盖 | DB 唯一用户日期与幂等请求约束；日记乐观版本条件更新；重复 AI 返回既有结果，生成中冲突有明确状态 |
| 暴力尝试 / 多实例限流 | Redis 原子限流；登录/注册/重设端点更严格；IP 从可信网关链取值并覆盖客户端同名头；限制短期窗口 |
| AI 账单与响应攻击 | 同意后加载本人证据；30秒超时，100KB响应体，JSON/固定引用校验；最多4个带TTL租约；MySQL全站每日请求预算，失败也占预算以免隐形重试消费 |
| 隐私记录导出/删除 | 本人分页导出，包含全部日记；删除账户级联业务数据；清空日记保留每日牌面；恢复备份后撤销全部会话 |
| 公网数据库 / 容器横向访问 | 仅网关公布端口；MySQL/Redis密码；应用/迁移DB账号分离；API/Web非root、只读文件系统、禁提权、去多余capability |
| 依赖与供应链 | 版本及锁文件、CI audit；GitHub Actions限制权限；框架和认证依赖单独锁定；容器基镜像仍需持续扫描与按digest记录发布 |
| 运维失误 | 启动拒绝不安全生产配置；持久卷、加密备份、密钥单独保管、恢复/回退说明；不用数据库管理工具暴露公网 |

## 测试应包含的证据

- 78 张牌与 64 卦、4096 种六爻组合、硬币分布、随机拒绝采样、固定引用校验。
- 真实 MySQL / Redis：跨用户读/改/删/AI都失败，注入角色不生效，重复请求只建一条记录，每日并发领取同一条，过期日记版本返回409。
- 管理员只能读主动共享内容，停止共享后不可列出；管理员没有日记写接口；停用即失效、降权即禁止。
- AES 篡改认证、上海午夜边界、共享限流计数。
- 受控 HTTPS 模型：引用不符拒绝、完成后不再调用、预算耗尽不调用、并发状态。
- TOTP enroll / 登录前置挑战 / 恢复码一次性使用。
- Chromium 桌面、iPhone WebKit、320px窄屏：主页、抽牌、六次起爻、账户/云端日记流程与无横向溢出。
- Docker 构建、正式配置校验、网关配置及带数据库的镜像运行验收。

## 仍需要真实环境验证

真实 SMTP 投递与域名认证、模型账号策略/计费、TLS与域名、国内网络可达性、服务器防火墙、日志/备份策略、容量与压力、外部渗透测试。源码测试不能代替这些条件。

应用层加密不阻止持有服务器密钥的运维人员解密，也不替代磁盘/备份加密。AUTH_SECRET / DATA_ENCRYPTION_KEY 必须分开保管；直接更换数据密钥会使旧记录无法解密，轮换前须备份并实施数据迁移。自托管服务器管理员权限需限制到实际需要的人员。

当前每 IP 的固定窗口限流配合客户端 IP 会在大型 NAT 网络下影响合法用户，应根据真实流量调整，并增加网关/WAF防刷；不宣称单独限流等于全网DDoS防御。应用有100KB模型响应上限和32KB请求上限，但仍需要网关连接与资源限制。

扫描失败应修复后才发布，禁止为了显示通过而关闭安全检查或忽略高危公告。CLI 使用的 deepmerge-ts/effect 安全 override 需要随 Prisma 更新重新确认兼容性；目前以真实迁移验证，未把高危旧版本保留下来。
