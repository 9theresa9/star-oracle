# 每日星笺 review 与部署

新增独立的每日入口，复用现有牌面和完整 78 张数据。每天抽一张正位牌，配编辑整理的提示、小行动和反思问题，之后可以留下心情与日记。真实 AI 状态仍由后端配置决定。

## 体验顺序

1. 首页点击“每日星笺”，或顶部“每日”。轻触卡片或领取按钮。
2. 刷新、返回和另开同源标签页，确认当天牌面保持一致。
3. 选择心情、填写文字并保存，重新进入后回看。
4. 打开星笺日记，回看并编辑过去的记录。
5. 清除单份或全部日记，确认每日牌面继续保留。
6. 复制星笺（不附带私人日记）；深入探索沿用这张牌，可进入现有基础解读及可选 AI 流程。
7. 手机与桌面、系统减少动态效果、200% 字号、跨本地午夜。

## 存储与日期

使用设备的本地年月日，不用 UTC 日期截断。结果与日记使用独立 localStorage key，保留最近 90 张。删除文字与心情时保留抽牌锁。浏览器清除全部数据、换设备或换浏览器会重新开始。

存储读写失败时，在当前页面保留结果并显示未持久化状态。当前页面的未保存草稿按日期暂留；关闭或刷新页面会丢失草稿。Web Locks 可用时，首次抽牌和日记变更在同源标签页间串行处理。没有 Web Locks 时使用同步读写与 storage 事件同步，不承诺跨进程原子性。

没有新增账号、数据库、收费项目或模型密钥。心情和日记不会自动发送给 AI；主动进入深入解读时，仅使用固定单张牌及原有问题。

## 部署

本功能在 feat/daily-starlight 分支，基于 feat/star-oracle-mvp，可独立 review。部署新版需要检出包含本功能的提交。

保留现有 .openai/hosting.json 的真实 project_id，不重复创建 Sites。npm run build 包含 /daily.js 和 /shared/daily.js；npm run preview:build 同样包含每日功能。

Sites 项目已注册，截至开始开发时尚无已发布版本。此任务没有终端，GitHub CI 构建产物不等于正式发布。部署使用 docs/DEPLOYMENT.md 中的官方流程，访问链接以真实成功结果为准。

## 验证

新增日期边界、重新加载、旧日编辑、清除日记、存储失败、损坏数据和 78 张提示覆盖的 Node 测试。浏览器流程覆盖每日入口、手机布局、复制外的日记操作、跨午夜、草稿、同源标签页，以及既有抽牌、起卦与模拟 AI 追问。实际通过状态以本功能提交的 GitHub Actions 为准。
